# 安全フックを依存コマンドが使えないときに fail-closed にする（中程度・想定入力範囲の改訂版）

## Context

`hook-pre-boundary.sh` は jq や `realpath -m` を使えないとすべての書き込みを許可し、`hook-post-secret-scan.sh` はスキャンを黙って省いていた。
初版の計画では jq と realpath を名前で挙げて事前に確認する形にし、ユーザーが差分を適用済み（未コミット）。

検証（イテレーション 1）で不合格になった。

- **指摘 1（テスト不足）**: 許可範囲ごとの「空なら拒否」のガードのうち 4 つ（`real_skills` / `real_repo_skills` / `real_home` / `scratch_base`）は、1 つずつ外してもテストが落ちない。`real_skills` を外すと全許可になることを実測
- **指摘 2（範囲外・重大）**: `cat` が無いとペイロードが空になり全許可、`dirname` が無いと `/skills` が許可される（HEAD からある挙動）。
  初版の「想定しない条件」に書いた「dirname・tr など…失敗しても許可の方向に倒れない」は、確かめずに書いた誤った前提だった

ワークフローの「想定入力範囲の改訂」（1 タスク 1 回まで。今回が 1 回目）として計画をやり直す。
あわせて防御の形を変える。名前を挙げたコマンドだけを確かめる形は列挙型の防御で、列挙から漏れたコマンドがそのまま穴になる（指摘 2 がその例）。
**判定・出力に効くすべての外部コマンド呼び出し（コマンド置換・`if` の条件・パイプラインの各段）で終了コードを確かめ、失敗したら拒否する** 構造にする。
防御の範囲は構文の形ではなく意味の単位で決める（検証で「コマンド置換」と書いた版がパイプラインの途中を取りこぼした）。

## 変更内容（適用済みの初版からの差分として作る）

### 1. `.claude/scripts/hook-pre-boundary.sh`

- **stdin を最初に読む**: `payload=$(cat) || fail_closed "…"`。依存コマンドの確認より前に読み切る。
  読まずに終了すると、Claude Code 側の書き込みがパイプの切断を受けうるため（警告 1）
- **判定に値を使うすべてのコマンド置換に終了コードの確認を付ける**: jq の確認より前は `|| fail_closed`、後は `|| deny`。
  対象は payload（cat）、`f`（jq）、各 realpath の呼び出し、`session_id`（jq）。`f_safe`（tr）は拒否理由の文言にだけ使うため対象外
  （tr が失敗しても理由が空になるだけで、拒否は維持されることを inspector が実測済み）
- **外部コマンドへの依存を減らす**: `hook_dir=$(dirname "$hook_path")` を bash のパラメータ展開 `${hook_path%/*}` に置き換える（`hook_path` は realpath の出力で必ず絶対パス）
- 空チェックのループは残す（成功の終了コードで空を返す場合の守り）
- 冒頭の jq / realpath の事前確認は残す（導入の案内を理由に出すため）

### 2. `.claude/scripts/hook-post-secret-scan.sh`

- **stdin を最初に読む**: `payload=$(cat) || scan_failed "…"`、`f` は `printf '%s' "$payload" | jq …` から取り出す
- **jq の終了コードを理由に入れる**: `|| scan_failed "入力JSONの解析に失敗しました（jq の終了コード $?）"`（警告 2）
- **grep の失敗を検出する**: パイプラインを段ごとに分け、1 段目（`grep -Ei "$detect" "$f"`）と 2 段目（除外パターンの照合 `grep -Evi`）のそれぞれで、終了コードが 2 以上（読み取れない・grep が無い・照合に失敗した）なら `scan_failed`。0 と 1（一致あり・なし）は従来どおり。3 段目の `grep -q .` は 2 段目の出力が空かどうかの判定に置き換え、外部コマンドを使わない
- **非 UTF-8 のバイトを含む行も照合する**: 1 段目と 2 段目の grep に `-a` を付ける。UTF-8 ロケール（ユーザーの環境は `ja_JP.UTF-8`）では、Shift_JIS や Latin-1 の文字を含む行を grep がバイナリとみなし、照合結果が空のまま終了コード 0 で終わるため（実測。1 段目だけに付けても 2 段目が同じ理由で空になる）
- **照合をバイト単位にそろえる**: 1 段目と 2 段目の grep を `LC_ALL=C` で実行する。UTF-8 ロケールでは不正なバイト列が `\S` などの文字クラスに当たらず、クォートなしの値の先頭にあるとシークレットを見逃すため。照合の結果をロケールに依存させない
- **検出精度の既知の限界をヘッダに書き足す**: `=` の前後の全角空白は空白として扱わない（C ロケールと同じ）、スマートクォートは除外パターンに当たらない、警告の JSON にパスをエスケープせずに埋め込む、NotebookEdit は対象外（settings.json の matcher）、macOS の BSD grep での `\S` の解釈は未確認

### 3. テスト

- `scripts/test_hook_pre_boundary.py`
  - 指摘 1: 許可範囲の変数ごとに、その変数の解決だけを失敗させるケース（`real_project` / `real_skills` / `real_repo_skills` / `real_home` / `scratch_base`）。
    書き込み先は、その範囲が `/` に化けたときに初めて許可されるパスにする（例: skills は `/etc/passwd`、home は `/.claude/projects/x/memory/a`）
  - 指摘 2: `cat` が無い（exit 2）、`dirname` が無い（判定が Linux と同じ）
  - `session_id` の取り出しだけ jq が失敗する場合に、スクラッチパッドを許可しない（範囲外の所見 I24 の穴）
  - 大きな payload（64KiB 超）で事前確認が失敗しても、stdin を読み切ってから exit 2 で終わる
- `scripts/test_hook_post_secret_scan.py`
  - `cat` が無い、grep が無い、対象ファイルを読み取れない（モード 0200）→ exit 2 とスキャン失敗の理由
  - grep の N 回目の呼び出しだけが exit 2 で失敗する（N = 2, 3）→ シークレットのあるファイルで exit 2 とスキャン失敗の理由
  - `LANG=ja_JP.UTF-8` で、シークレットの行に Latin-1 / Shift_JIS のバイトや NUL を含むファイル → 警告が出る（C ロケールでも同じ結果になる）。バイトは行末のコメントだけでなく、クォートなしの値の先頭にも置く
  - 解析失敗の理由に jq の終了コードが含まれる
  - 大きな payload でも stdin を読み切る

## 🛡️ 想定入力範囲（改訂）

| 項目 | 内容 |
|---|---|
| 信頼境界 | フックの実行環境（PATH とそこにあるコマンド）は信頼しない。payload（Claude Code が生成）も信頼しない |
| 想定する入力の軸 | **フックが判定に使う外部コマンドすべて** × {動く, PATH に無い, 非 0 で終わる, 特定の引数でだけ失敗する}。境界フック: cat、jq、realpath / grealpath（realpath は `-m` 非対応も含む）。シークレットスキャン: cat、jq、grep。payload: {正しい JSON, 壊れた JSON, `file_path` が無い, 64KiB を超える}。スキャン対象: {シークレットあり, なし, 存在しない, ディレクトリ, 読み取れない}。境界フックの書き込み先の軸は既存テストのものを維持する |
| 規模の上限 | payload は 1MiB 程度まで。1 回の起動で数十ミリ秒程度 |
| 実行環境の前提 | bash（Linux / WSL と macOS）。`LC_ALL=C`（境界フック）。シークレットスキャンは照合を `LC_ALL=C` で行い、起動時のロケールは C と `ja_JP.UTF-8`（ユーザーの実環境）の両方を想定する（どちらでも同じ結果になること）。macOS は実機では検証せず、`-m` を受け付けない realpath のスタブで再現する |
| 想定しない条件 | 外部コマンドが成功の終了コードで誤った出力を返す場合／フックがそもそも起動しない場合（bash が無い・実行権限が無い。settings.json の `onFailure: "block"` の領域で今回は変更しない）／tr の失敗（拒否理由の文言が空になるだけで拒否は維持される。inspector が実測済み）／シークレットスキャンの検出精度（正規表現による推測で、検出漏れ・誤検知はヘッダの「既知の限界」として扱う。今回の範囲は、失敗したときの扱いと、結果がロケールに依存しないこと） |
| 判定の不変条件 | 境界フック: 判定に使うすべてのコマンドが成功し、書き込み先の実体パスが許可範囲の配下にあると判定できたときだけ許可し、それ以外はすべて拒否する。シークレットスキャン: スキャンを最後まで実行できなかったときは、必ずそのことを Claude に伝え、実行できたときの結果は起動時のロケールに依存しない |
