# 実験: 「単純」分類から事前調査フェーズを外す

- 作成日: 2026-09-23
- 状態: **実験中（導入済み。効果は次の代表的なタスクで測る）**
- 根拠: `~/.agents/CLAUDE.md` の「エージェント構成の見直し方針」

## 背景

`~/.agents/CLAUDE.md` は、フェーズを「能力の補完」と「検証の独立性」に分け、前者を「モデル更新で不要になりうる。削減候補」と定めている。その例として**筆頭に挙がっているのが事前調査**である。

しかし `plans/` に残る実施済みの実験3件は、いずれも調査フェーズに触れていない。

- `plans/2026-09-15-implementer-opus.md`: implementer のモデル変更（sonnet → opus）
- `plans/2026-09-22-inspection-scope.md`: 想定入力範囲の宣言と検証のブロック判定の限定
- `plans/2026-09-23-approach-fallback.md`: 同一根本原因での再不合格をアプローチ差し戻しへ回す

3件とも**追加方向**の変更であり、削減方向の実験は一度も行われていない。その結果、現状は最小の「単純」分類（1-2ファイル、ロジックあり）でも4エージェント（investigator → tester → implementer → inspector）が起動する。各サブエージェントはコールドスタートで文脈を再導出するため、調査レポートの内容は tester・implementer がそれぞれ改めて対象コードを読む作業と重複しうる。

## 仮説と判断

- 事前調査は「検証の独立性」ではなく「能力の補完」に属するフェーズである。独立した第三者の視点を担保するためのものではなく、実装者が単独では把握しきれない文脈を先に集めるためのものであり、モデルの更新で不要になりうる
- 1-2ファイルに閉じる変更では、tester が RED を書く過程で対象コードと既存のテストパターンを読む。implementer も GREEN の過程で同じ範囲を読む。したがって独立した調査フェーズが上積みする情報は小さいと見込む
- **変数は「単純」分類からの `@code-investigator` の除去の1つのみ**。「中程度」「複雑」分類は調査フェーズを維持し、`@code-investigator` の定義そのものも変更しない
- 影響範囲の見立てを外した場合の退路として、着手後に 1-2 ファイルに収まらないと判明した時点で「中程度」以上へ再分類し、調査・計画フェーズへ戻す規定をパターン3に併記する

`~/.agents/CLAUDE.md` の「削減の実験手順」との対応: 手順1（削減候補を1つだけ選ぶ）は本記録で完了し、複数フェーズの同時削減は行っていない。現在は手順2（代表的なタスク2〜3件を削減構成で実施する）の入口にある。手順3（品質の比較）は下の「評価基準」、手順4（確定または差し戻し）は下の「判定」で行う。

## 評価基準

普段の代表的なタスク2〜3件を、「単純」分類で調査フェーズを省いた構成で実施する。

| 観点 | 計測方法 | 期待 |
|---|---|---|
| 検証イテレーション数 | 合格までのイテレーション数 | 変更前と同等。悪化なし |
| 既存パターンからの逸脱 | 調査フェーズが担っていた「既存パターンの抽出」が失われた結果、プロジェクト規約と異なる実装になった件数 | 0 |
| 影響範囲の見落とし | 1-2ファイルの想定が外れ、着手後に「中程度」以上へ再分類した回数 | 0〜1。頻発するなら分類基準の側の問題 |
| tester ⇔ implementer 差し戻し | 差し戻し回数 | 変更前と同等 |
| 所要時間・起動数 | 1タスクあたりのエージェント起動数と体感の所要時間 | 起動数は4→3。時間は短縮 |

## 判定

- 悪化がなければ削減を確定し、`development-workflow.md` を更新する。次の実験は「中程度」分類への適用とする
- 既存パターンからの逸脱が出た → 戻す。調査フェーズは「能力の補完」ではなく既存パターンの抽出という別の役目を担っていたことになる
- 影響範囲の見落としが出た → 戻す
- 再分類が頻発する（見落としではなく分類の判断が毎回揺れる） → 削減の可否ではなく、分類基準（1-2ファイル）の側を見直す

## 交絡の管理

- implementer は opus のまま固定する
- **並走する実験が3件ある**。`plans/2026-09-22-inspection-scope.md`（評価データ未取得）、`plans/2026-09-23-approach-fallback.md`（導入直後）、そして本実験で4件目となる
- `~/.agents/CLAUDE.md` は「削減候補を1つだけ選ぶ（複数フェーズを同時に外さない）」と定めており、**外すフェーズは1つ**である点で本実験は規定を満たす。他の2件は追加方向の変更であり、フェーズの削減ではない
- ただし計測期間には複数の導入済み変更が同時に効く。効果の帰属は、**発火した経路の記録**（範囲改訂か、アプローチ差し戻しか、調査省略後の再分類か）で切り分ける
- 未処理のスキルフィードバックの反映を同時に行わない

## 除外範囲

- 「中程度」「複雑」分類からの `@code-investigator` の除去
- `@code-investigator` のエージェント定義の変更
- 計画フェーズの削減
- パターン番号の振り直し
