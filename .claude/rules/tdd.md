# TDD ルール

## 適用範囲

TDD は**テストで検証できる振る舞いを変更・追加する実装**に適用する。ロジック（条件分岐・状態管理・データフロー・API・マークアップ構造）に触れる変更は、規模に関わらず適用範囲内である。詳細な除外基準は `development-workflow.md` の分類「軽微」と `/tdd` スキルの「適用範囲の早期判定」を参照。

## 原則

**適用範囲内のコードを実装する際は、必ずテストを先に書くこと。**

プロダクションコードの実装より前にテスト（または種別に応じた失敗根拠）が存在しない場合、その実装は TDD に違反している。ただし failing テストが常に必須とは限らない。RED の形は変更の性質（behavior / static diagnostic / characterization baseline / invariant guard）により異なり、純粋なリファクタリングや型・設定移行、既存ガードへの回帰保護では failing テストを要求しない。詳細は `/tdd` スキルの「🧭 RED の種別」を参照。

## Red-Green-Refactor サイクル

すべての実装はこのサイクルに従うこと:

1. **Red**: 失敗するテスト（または種別に応じた失敗根拠）を用意する
2. **Green**: テストが通る最小限のコードを書く
3. **Refactor**: テストを通したままコードを整理する

このサイクルを1テストケースずつ繰り返す。複数のテストをまとめて書いてから実装するのは禁止。詳解は `/tdd` スキルの「🔧 Red-Green-Refactor 詳解」を参照。

## オーケストレーション時の例外

以下のいずれかに該当する場合、tester / implementer 分離ワークフロー（`development-workflow.md` の Phase 3a/3b、`/tdd` スキルのオーケストレーション手順）の一部として動作しており、この例外が適用される:

- 自分が tester / implementer 専任のエージェント定義（`@tester` / `@implementer`）で起動されている
- 委譲プロンプトに RED / GREEN フェーズの明示がある

例外の内容:

- tester: RED フェーズとして、スコープ内の全テストケースを一括作成してよい（TDD 違反ではない）
- implementer: 受領した failing テストを1つずつ GREEN にする（「1サイクルずつ」の原則は実装順序に適用する）

上記のいずれにも該当しない場合（メインセッションや汎用エージェントがテスト作成と実装の両方を担う場合）は、従来どおり1テストケースずつのサイクルで進める。

## 禁止事項

- プロダクションコードを先に書き、後からテストを追加する
- 適用範囲内の実装を RED（種別に応じた失敗根拠）なしで行う
- 適用範囲内の変更を「シンプルだからテスト不要」と自己判断してテストを省略する（範囲の判定は「適用範囲」の基準のみで行う）
- すべてのテストケースをまとめて書いてから実装する（1サイクルずつ進めること。ただしオーケストレーション時の例外を参照）

## 参照スキル

以下のいずれかに該当する場合は `/tdd` スキルを参照する:

- **テスト対象自身が破壊的な副作用（ファイルの作成・削除・リネーム、設定の書き換え）を持つとき**。テストの失敗が実環境の破壊に直結するため、隔離テスト環境の設計指針と 3 重防御を必ず確認する
- tester / implementer 分離のオーケストレーションを行うとき
- RED 種別（static diagnostic / characterization baseline / invariant guard）の判定が必要なとき（リファクタリング・型/設定移行・既存ガードへの回帰保護等）
- 変異試験でテストの実効性を検証するとき
- 新規ファイル作成タスク、または外部プロセス・スタブ・カスタムハーネスを伴うテストを書くとき（充足可能性チェック・ハーネス自身の検査）
- 環境依存（ロケール・探索パス・タイムゾーン・依存コマンドの可用性）に左右されるテストを書くとき（前提条件を満たせないケースの SKIP 可視化）
- バグ修正で同根の入力空間（基数・ロケール・符号・空白・オーバーフロー等）を洗い出すとき
- 検証フェーズ不合格を受けて実装に再入場するとき、または RED 中に要件・期待値が変更されたとき
- テスト設計パターン・命名規約等の詳細な指針が必要なとき

上記のいずれにも該当しない単純な実装は、このルールの記載のみで進めてよい（スキルの読み込みは不要）。
