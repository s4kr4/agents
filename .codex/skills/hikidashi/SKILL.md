# Shared Memory

通常の作業で共有メモリを参照・保存するためのスキル。会話全文や一時的な作業ログは保存しない。

## 作業開始時

過去の好み、制約、判断が現在の作業に影響する可能性がある場合、最初に `get_context(project_id="対象プロジェクト")` を呼ぶ。必要な語句が決まっている場合は `search`、経緯が必要な場合は `history` を使う。`philosophy` タグの作業方針はセッション開始時にフックで注入済みのため、改めて取得しない（注入が無い場合だけ `search` で取得する）。

## 作業中・完了時

将来の判断を変える確認済みの知見だけを短く候補にする。完了時に既存記憶との重複・矛盾を確認し、保存する場合は `write_memory` で要約する。保存前に `list_tags` で既存タグを確認し、同義のタグを増やさず可能な限り再利用する。`philosophy` タグはユーザーと確定した作業方針専用。ユーザーの明示なしに付与しない。ユーザーの1回の指示から好みを保存する場合は、適用範囲（今回だけか・常にか・条件付きか）を推測で広げない。範囲が分からなければ、保存する前に確認する。

保存する対象は、ユーザーの恒常的な好み、開発環境・ツール設定、繰り返し参照するプロジェクトの決定事項、協働上の確認済みの知見。会話全文、一時的な作業内容、未検証の推測、リポジトリに既に書かれている事実は保存しない。

## 本文の書き方

既存の記憶を更新するときは、`write_memory` の `change_message` にコミットメッセージのような短い変更の要点を指定する（例: `検証時の保存先の隔離手順を明確化`）。本文の変更前後を複写せず、1文・80文字以内にする。CLI では `write-memory --change-message` を使う。

`write_memory` の summary は Markdown として Vault に保存され、`get_context` / `search` の結果としてそのまま読まれる。改行のない1段落に詰めると結論・条件・実例の境目が読み取れないため、意味の区切りで改行する。

- 1文目に結論（何をするか・何が成り立つか）を書く。検索結果で最初に読まれる部分のため
- 1行に1文を基本とし、句点で改行する。読点で長く続く文は分ける
- 意味のまとまりが変わるところで空行を入れ、段落を分ける。順番の目安は「結論 → 理由・条件 → 実例（確認日） → 判断への影響」
- 並列する項目は文中に (1)(2) と詰めず、箇条書きにする
- 1〜2文で済む記憶は段落に分けない。見出しは複数の節を持つ長い記録に限る

```markdown
Claude Code のコマンドフックで安全上の判定をするときは fail-closed に書く。

PreToolUse は exit 2 でツール呼び出しを止め、stderr が理由になる。
exit 1・127 などは止めないエラーで、呼び出しはそのまま進む（2026-10-29 に公式ドキュメントで確認）。

- 拒否の手段を jq など壊れうる依存に頼らず、失敗時は stderr + exit 2 に落とす
- stdin は依存の確認より先に読み切る
```

## MCP ツール

- `get_context`: 現在の応答に使う文脈を取得
- `search`: 現行記憶を検索。`tags` を渡すと、指定した全タグを持つ記憶だけに絞り込む（AND）
- `history`: 記憶・セッション・イベントの経緯を検索
- `write_memory`: 確認済みの知見を保存。`tags`（タグのリスト）・`related`（関連記憶の `id` のリスト）を任意で指定できる。省略時は既存のタグ・関連を維持し、空リスト `[]` を渡すと全消去する。`directory`（`global`・`project` のみ、`/` 区切りで最大3階層）を指定すると、`memory/global/philosophy/<slug>.md` のようなサブフォルダに分類して保存する。directory は記憶の同一性に含まれるため、既存の記憶を更新するときは、その `id` に含まれるサブフォルダと同じ directory を渡す（省略すると別の記憶として作られる）
- `related`: 指定した記憶に共有タグ・明示リンクで関連する記憶を探す。各ヒットに `score`・`matched_tags`・`link`（`outgoing`/`incoming`/`mutual`/`none`）が付き、参照先が撤回済みの場合は `dangling` に分離される
- `list_tags`: 既存のタグと件数を件数降順で取得する
- `update_metadata`: 既存記憶のタグ・関連だけを本文を変えずに更新する。`memory_id` は必須、`tags`/`related` は省略可（両方省略はエラー）。既存記憶のタグを直すだけのときは、summary を再送する `write_memory` ではなくこちらを使う
- `forget`: ユーザーが明示した記憶を archive へ移動。`memory_id` は `search`/`history`/`get_context` が返す `id`（`global/<slug>`、`global/philosophy/<slug>`、`projects/<project>/<slug>` などディレクトリ階層を含む形式）をそのまま渡す。ディレクトリを省いた裸のスラグは拒否される

`write_memory` の日常保存では `session_id` を省略できる。`scope="project"` では `project_id` を指定する。`hikidashi-distill` が元セッションから抽出するときだけ、元の `session_id` を必ず渡す。

保存形式、保存先、CLI フォールバック、接続設定は `$HIKIDASHI_MCP_PATH/README.md` を参照する（基盤は別リポジトリ hikidashi-mcp にあり、clone の位置を指す `HIKIDASHI_MCP_PATH` が未設定の端末では参照できない）。MCP の起動・権限・保存エラーは `hikidashi-doctor` スキルで診断する。
